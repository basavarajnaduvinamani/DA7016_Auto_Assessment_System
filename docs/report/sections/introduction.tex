\section{Introduction}
Marking an exam booklet requires more than assigning a total. A teacher has to recognise which answer belongs to which question, judge it against the relevant rubric, explain deductions and decide which uncertain cases merit another look. Handwriting, mixed languages, diagrams and answers written out of order complicate this work. A fluent explanation of a mark is not sufficient if it cannot be traced to something the student actually wrote.

Auto-Assessment addresses this problem by treating the teacher's rubric as an explicit contract. Inputs are an exam specification containing questions, criterion descriptions and model answers, together with complete answer sheets. Outputs preserve the link between an awarded criterion and evidence from the answer. The intended role is to support a teacher's marking and feedback workflow; the system does not establish an independent authority over the rubric or the final grade.

The project's educational bar is \emph{feedback specific enough for a student to improve}. Agreement with human marks is a necessary check on the grading process, but it cannot demonstrate that a correction helps a learner. The evaluation therefore separates score agreement, robustness, reading errors and the effect of feedback on a subsequent answer. These are proposed measurements with pending results, rather than interchangeable claims of success.

The implemented contributions are:
\begin{itemize}
  \item a full-sheet pipeline with explicit contracts for page reading, segmentation, criterion grading and report generation;
  \item evidence enforcement, bounded awards and complementary advocate and critic passes;
  \item a conservative confidence mechanism that marks uncertain answers for teacher review;
  \item feedback verified against awarded marks, displayed both as an evidence report and as red-ink annotations;
  \item an evaluation harness and results pack that separate saved measurements from report presentation.
\end{itemize}
These are engineering contributions supported by the repository implementation. Their educational value and generalisation to real handwritten scripts require the study described below.
